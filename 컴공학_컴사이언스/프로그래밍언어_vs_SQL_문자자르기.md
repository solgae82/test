# 📜 컴퓨터 과학 비하인드 스토리 최종 요약 노트

20년 동안 매일 쓰면서도 무심코 지나쳤던 코드 속 설계자들의 철학과 역사적 배경을 정리한 나만의 비밀 노트입니다.

---

## 1. 문자열 슬라이스 `(0, 3)` (파이썬 등 현대 언어의 관점)
* **철학**: 컴퓨터 메모리 효율과 수학적 우아함.
* **작동 방식**: `[시작, 끝)` 반열린 구간 ➡️ 0번 인덱스부터 3번 미만(0, 1, 2)까지 자름.
* **통일된 이유**: 
  1. `끝 번호 - 시작 번호 = 글자 수`가 바로 나오는 직관성 (`3 - 0 = 3`글자).
  2. `(0, 3)` 이후 바로 `(3, 6)`으로 이어 자를 때 톱니바퀴처럼 딱 맞아떨어져 프로그래머의 `+1`, `-1` 실수를 방지함.
* **역사**: 컴퓨터 과학의 거장 에츠허르 다익스트라(Dijkstra) 박사의 1982년 논문 이후 '보이지 않는 표준'으로 정착.

## 2. 데이터베이스 `SUBSTRING` (SQL의 관점)
* **철학**: 일반 비즈니스 사용자와 타자수도 바로 이해할 수 있는 **인간 중심의 직관성**.
* **작동 방식**: `SUBSTRING(문자열, 시작 위치, 가져올 글자 수)` ➡️ 1부터 시작하여 2번째 글자부터 딱 3글자만 가져옴.
* **탄생 배경**: 1970년대 IBM 연구소에서 프로그래머가 아닌 경리, 서기 등 비전공자도 매뉴얼만 보면 쓸 수 있도록 '영어 문장 구조(SEQUEL)'를 본떠 만듦. 인간은 숫자를 1부터 세기 때문.
* **엔진의 배려**: 프로그래밍 언어와 헷갈린 개발자들이 실수로 시작 위치에 `0`을 넣어도, DB 엔진이 알아서 `1`로 치환하여 정상 결과를 출력해 줌.

## 3. 엑셀(Excel)과 VBA의 흥미로운 동거와 혼종 사건
* **관점의 통일**: 엑셀 시트 함수 `=MID("ABCDE", 2, 3)`과 VBA 매크로 함수 `Mid("ABCDE", 2, 3)`은 모두 SQL처럼 **1부터 시작하고 글자 수를 지정**함. 엑셀을 쓰던 직장인들이 매크로를 배울 때 혼란을 겪지 않도록 배려한 결과.
* **배열(Array)의 반전**: 하지만 VBA 내부에서 데이터를 담는 '배열'을 다룰 때는 컴퓨터 언어 본연의 본능을 버리지 못해 **0부터 시작**함.
* **끔찍한 혼종의 예시**:
  ```vba
  MyArray = Split("사과 바나나 포도", " ")
  MsgBox MyArray(0)        ' 배열에서 "사과"를 꺼낼 때는 0부터 시작!
  MsgBox Mid("사과", 1, 1)  ' "사과"에서 "사"를 자를 때는 1부터 시작!
  ```
* **해결책**: 이 이중스파이 같은 혼란 때문에 개발자들이 분노하자, MS는 코드 맨 위에 `Option Base 1`을 적으면 배열 인덱스도 1부터 시작하도록 강제 통일하는 치트키를 제공함.

## 4. 앞으로의 방향: 파이썬(Python) vs VBA
* **파이썬 선택 이유**: 엑셀 파일 크기가 수십 MB를 넘어가거나 대용량 데이터 정제, 웹 크롤링, AI/머신러닝 및 타 시스템과의 연동 등 확장성이 필요할 때 압도적으로 유리함. 최근 MS 엑셀에 내장 파이썬(`=PY()`)이 공식 도입되며 시너지가 극대화됨.
* **VBA의 영역**: 별도 프로그램 설치가 불가능한 보안 환경, 엑셀 창 자체의 UI(버튼, 팝업 등)를 세밀하게 제어하는 자동화, 기존에 구축된 사내 매크로 장부 유지보수에는 여전히 현역으로 대활약 중.
