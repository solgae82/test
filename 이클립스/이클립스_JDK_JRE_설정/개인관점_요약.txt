Installed JREs 와 JRE System Library 와 Java Compiler 의 삼각관계

1) Window > Preferences > Java > Installed JREs 

	(전체 설정 중 1곳)

	- 실행시 필요한 JRE 등록하는 곳 (개발자가 직접 등록)
	- 체크박스에 체크되면 기본 실행 JRE가 됨- 프로젝트 JRE는 이 등록 기준을 따른다
	
	예) 현재 java 8, java17 이 등록되어 있고 기본은 'java8' 설정되어 있다고 가정.

	[v] java8(default) , C:\jdk\java8
	[ ] java17 , C:\jdk\java17

2) 프로젝트 우클릭 > properties > Java Build Path > Libraries > Add Library > JRE System Library > Systme library
	
	(프로젝트 설정 3곳 중 1곳)

	[ ] Execution environment: - 내가 등록한 JRE가 아닌, 이클립스가 태어날때 인식할 수 있었던 [표준 실행 환경 목록].
		- 실제 실행 환경은 아니고, [표준 실행 환경 목록]만 있는 상태(템플릿 처럼)
		- 이 녀석은 Intalled JREs 를 바라보고 있다
		- 이 목록명 중 JavaSE-1.8을 선택하면, Intalled JREs 의 등록된 JRE 중에서 해당되는 JRE를 매핑 시켜준다.
		- 만약 등록되지 않은 JavaSE-20 을 선택했다면 'JavaSE-20(unbound)' 라는 형식으로 등록될 것이다.
		(실제 매핑된 JRE가 없으므로, 에러가 잔뜩 떨어지는 것은 덤.)
		- 이 형식을 사용하는 이유는 다른 곳으로 프로젝트를 공유할때, 공유된 컴 환경에서는 프로젝트가 요구하는 
		정확한 jdk/jre 경로위치가 아닌, 요구되는 jdk/jre만 설정해주면 된다는 이점이 있다.

		- 등록 예)
			JRE System Library [JavaSE-1.8]

	[ ] Alternate JRE: 
		- 원조 설정 방식
		- 개발자가 직접 jdk/jre 위치를 해당 컴 환경의 특정 경로로 설정해서 인식시키는 방식
		- 이렇게 설정하면, 프로젝트 공유시, 공유된 컴 환경에도 정확히 똑같은 위치에 jdk/jre가 설정되어 있어야 인식하고 동작하게 될 것이다. 
		그렇게 설정하라고 알려주지 않으면, 개발자는 헤메게 된다.

		등록 예)
			JRE System Library [java8]

	[ ] Workspace default JRE (java8): 

		- 말 그대로 (Installed JREs 에서 기본 체크 설정한) 디폴트 JRE를 쓰겠다는 것
		- 이것도 문제가 프로젝트 공유시, 공유된 컴 기본 설정값이 다르면 안 될 것 같다(테스트 해보지 않아서 정확히는 모름)

		등록 예)
			JRE System Library [java8]

3) 프로젝트 우클릭 > properties > Java Compiler(프로젝트 설정 3곳 중 1곳)

	- 컴파일시 문법 검사를 어느 버전으로 할까를 정해 주는 곳
	- 이 녀석은 Java Build path > Libraries > JRE System Library 를 바라본다
	- 만약 [표준 실행 환경 목록] 중에서 설정했다면, 부가적으로 컴파일 문법 검사 버전을 설정한 [표준 실행 환경 목록]과 맞춰주고 자동 잠궈준다
	- 만약 Alternate JREs 로 직접 설정했다면, 수동으로 정했으니, 검사 레벨도 수동으로 직접 지정 선택해야한다.(니가 정해라)

-------------------

요약: 
전혀 다른 메뉴 같아도 저 3메뉴는, 서로 영향을 주는 관계임에 틀림 없다. 
저 관계를 모르고 이클립스 java 버전을 맞추려고 하면, 분노 분출 욕만 수 없이 하게 될 것이다.
