
<전체 설정 2곳 , 프로젝트 설정 3곳의 먹이사슬 구조>

-------------------(상식 1)

과거버전들:
	- eclipse.ini 에 -vm 옵션으로 이클립스 구동용 jdk 프로그램을 지정했었다.
		(이런 형식으로)
		-vm
		D:\JAVA\bin\javaw.exe

	- Window > Preferenece > Java > Installed JREs 도 과건엔 직접 JDK를 등록해 줬었다.


최근 버전들
	- eclipse.ini 에 -vm 옵션을 주지 않아도 기본 내장된 JDK로 구동된다.
	
	- Window > Preferenece > Java > Installed JREs 도 기본 내장된 JRE 가 1개 등록되어 있다.
	
		(예)
		D:\sts\sts-4.15.1.RELEASE\plugins\
		org.eclipse.justj.openjdk.hotspot.jre.full.win32.x86_64_17.0.3.v20220515-1416
		\jre\lib\jrt-fs.jar

이클립스가 실행시 java을 찾는 순서
	1. eclipse.ini 파일 확인: 이클립스 설정 파일에 -vm 옵션으로 특정 자바 경로를 강제로 지정해 두었는지 먼저 봅니다.
	2. 내장 플러그인 자바 사용: 지정된 게 없다면, 방금 말씀하신 plugins 안의 내장 자바(JustJ)를 이용해 이클립스를 실행합니다.
	3. 시스템 자바 확인: 만약 내장 자바가 없는 구버전 이클립스라면, 그제야 내 컴퓨터 시스템 변수(PATH나 JAVA_HOME)에 등록된 자바를 찾아 나섭니다


-------------------(상식 2)

과거 방식: eclipse.ini 파일에 -vm으로 구동용 JDK 경로를 수동 지정해야 했고, 
Installed JREs도 개발자가 직접 추가해야 했습니다.

현재 방식: -vm 설정을 생략해도 이클립스 내부에 자체 내장된 JDK 경로를 기본으로 바라보며, 
Installed JREs에도 이 내장 JRE가 자동으로 등록되어 제공됩니다.

변화의 이유: 말씀하신 대로 Eclipse JustJ 프로젝트 덕분입니다. 
이클립스 재단에서 자바 미설치 사용자의 진입 장벽을 낮추고 구동 안정성을 확보하기 위해 배포판에 JustJ JRE를 기본 포함하기 시작한 결과입니다.

컴파일러 특징: 짚어주신 것처럼 이클립스는 예전이나 지금이나 Oracle JDK/OpenJDK의 javac 대신, 
자체 내장된 ECJ(Eclipse Compiler for Java)를 사용해 코드를 실시간으로 컴파일합니다. 
Installed JREs는 주로 컴파일된 클래스를 실행(Run)하거나 자바 표준 라이브러리(API) 코드를 참조할 때 사용됩니다.

----------- JDK, JRE 등 설정할 포인트들(5곳)

전체 설정 (Workspace Level) , 2곳

	이클립스 메뉴의 Window -> Preferences에서 설정하며, 앞으로 만들 모든 프로젝트의 기본값이 됩니다.

	1) Installed JREs: 
	
	메뉴경로: Window > Preferenece > Java > Installed JREs
	
	이클립스에게 "내 컴퓨터에 설치된 JDK/JRE들이 어디에 있는지" 알려주는 메뉴입니다. 
	여러 개 등록해 두고 선택할 수 있습니다.

	2) Compiler Compliance Level: 
	
	메뉴경로: Window > Preferenece > Java > Complier > JDK Compliance > Compiler Compliance Level
	
	자바 소스 코드를 컴파일할 때 기준이 되는 자바 버전을 지정합니다.
	
		★ 주의:
		- 여기서 주의해야할 것이, 내가 설정한 JDK 버전 기준으로 사용할 수 있는 컴파일러 목록이 나오는게 아니다.
		- 이클립스가 출시될때 자체로 가지고 있는 ECJ 컴파일러 기준이 나오는 것이다.(이클립스용 내장 JDK)
		- 그러므로 내가 설정한 JDK로 컴파일 하는게 아니고, 이클립스 자체 내장된 ECJ 컴파일러를 쓴다.
		
	
프로젝트별 설정 (Project Level) , 3곳

	프로젝트를 우클릭한 뒤 Properties에서 설정하며, 전체 설정보다 항상 우선순위가 높습니다. 
	하나의 이클립스 안에서 자바 8 프로젝트와 자바 17 프로젝트를 동시에 돌릴 수 있는 비결입니다.

	3) Java Build Path (Libraries 탭): 
		해당 프로젝트가 코드를 컴파일하고 실행할 때 사용할 구체적인 JDK/JRE 라이브러리를 지정합니다 
		(Installed JREs에 등록된 것 중 선택).

	4) Java Compiler: 
		해당 프로젝트만 전체 설정과 다른 컴파일러 버전을 쓰고 싶을 때 체크(Enable project specific settings) 후 버전을 변경합니다.

	5) Project Facets (Web 프로젝트 등에서 중요): 
		프로젝트의 전반적인 기술 스펙 버전을 정의하는 곳입니다. 
		여기에 설정된 Java 버전과 Java Compiler 버전이 일치해야 설정 오류가 나지 않습니다.
		
한줄 요약: 
	이클립스 자체를 켜기 위한 Java가 필요하고, 
	내가 코딩해서 빌드할 프로젝트용 Java가 따로 있으며, 
	프로젝트 설정은 전체 설정을 덮어쓸 수 있습니다.
	

------------------- 1. 전체 설정 2곳


1) Installed JREs 
	
	JREs 라고 이름이 명명되었다고 하더라도 JRE만 등록하지 말고, JDK 를 등록하자(이유가 있다)
	이클립스 자체 컴파일러로 컴파일 한다고 해도, 
	실제 현업에서는 Installed JREs 메뉴에 JRE 폴더가 아닌 JDK 폴더 경로를 등록하는 것이 절대적인 정석입니다.
		
		이유: 자바 개발을 하다 보면 소스 코드 컴파일 외에도 자바 공식 문서(src.zip 소스 코드 보기), 
		디버깅 기능, 혹은 메이븐(Maven)/그레이들(Gradle) 같은 빌드 도구 연동이 필요한데, 
		이 도구들은 이클립스 내장 컴파일러가 아니라 진짜 JDK의 기능들을 요구하기 때문입니다

		(이름은 JREs 지만, 등록은 JDK로 한다)
		
2) Compiler Compliance Level
	
	이클립스의 자체 컴파일러(ECJ)는 매우 똑똑해서 
	"하나의 컴파일러 프로그램이 하위 버전 문법을 모두 흉내 낼 수 있는 능력"을 가지고 있습니다.

	만약 내 이클립스가 최신 버전이라 내장 컴파일러가 Java 21까지 지원한다면, 
	이 컴파일러 하나가 Java 1.4 버전부터 5, 6, 7, 8, 11, 17, 21까지의 문법을 모두 지원할 수 있습니다.

	그래서 Java > Compiler > JDK Compliance 메뉴를 눌러보면 
	내 PC에 깔려있지도 않은 온갖 자바 버전들이 리스트에 전부 나오는 것입니다.

	JDK Compliance 버전 설정의 진짜 의미: "문법 검사기"
		이 메뉴에서 버전을 선택하는 것은 "이클립스 컴파일러야, 
		내가 지금부터 코딩할 테니까 딱 이 버전 문법에 맞는지 검사해 줘"라고 가이드를 주는 것입니다.
		
	핵심: 
		결국 이클립스 전체 설정(Global)의 핵심은 
		"내가 문법 검사 기준으로 삼을 버전(Compiler Compliance)과, 
		실제로 그 버전에 맞는 부품을 대줄 자바 경로(Installed JREs)의 버전을 
		서로 짝짜꿍(일치)하게 맞추는 것"입니다
		
	----------- 자동 연동 vs 강제 고정

	프로젝트 우클릭 -> Properties -> Java Compiler
	 [v] Enable project specific 
	 [v] Use compliance from execution environment 'JavaSE-1.8' on the 'Java Build Path'
	 Compiler compliance level: 1.8 (비활성화)
	 
	프로젝트 우클릭 -> Properties -> Java Build Path -> Libraries
	JRE System Library [JavaSE-1.8] 가 선택되어 있다
	(그러므로 위 메뉴가 1.8 고정으로 비활성화 되어 있는 것이다)
	 
	① 체크된 상태: Use compliance from execution environment... (권장 방식)
		(자동 연동) 의미: 
		"이 프로젝트의 Java Build Path에 등록된 자바 라이브러리(Execution Environment) 버전을 
		그대로 컴파일러 버전으로 자동 연동하겠다." 라는 뜻입니다.

		차이점: 
		만약 나중에 프로젝트 속성(Java Build Path)에서 자바 표준 실행 버전을 JavaSE-1.8에서 JavaSE-11로 변경하면, 
		컴파일러 버전도 알아서 11로 자동 업데이트됩니다. 
		개발자가 두 번 일하지 않게 해주는 스마트한 연동 옵션입니다. 
		그래서 선택 박스가 비활성화(잠금)되는 것입니다. 
	
	② 체크 해제하고 1.8을 직접 선택한 상태: 
		(강제 고정 방식)의미: 
		"빌드 패스에 자바 뭐가 들어오든 상관없고, 
		내 컴파일러 문법 버전은 무조건 1.8로 강제 고정하겠다." 라는 뜻입니다.
		
		차이점: 
		나중에 Java Build Path에서 자바 라이브러리를 JavaSE-11로 올리더라도, 
		컴파일러 문법 검사기는 여전히 1.8에 머물러 있습니다. 
		이 경우 개발자가 컴파일러 메뉴에 와서 직접 11로 또 바꿔줘야 합니다.

	
------------------- 2. 프로젝트 설정 3곳	
	
	
프로젝트에서 설정 3곳 나눈 이유
	
	Java Build Path (부품 공급관):
		하는 일: 
			실제 컴파일과 실행에 필요한 진짜 JDK 라이브러리 파일 경로를 연결해 줍니다.
			
		한계: 
			만약 Java Compiler만 있고 Build Path가 없다면, 
			이클립스는 문법 검사는 통과시켜도 
			"실제 String 클래스 부품이 없어서 컴파일을 완료할 수 없습니다"라는 에러를 냅니다.
		
	Java Compiler (문법 검사관):
		
		하는 일: 
			내가 키보드로 타이핑하는 소스 코드 문법만 검사합니다. 
			(예: "자바 8 버전이니까 람다식 써도 돼!")
			
		한계: 
			얘는 문법만 볼 뿐, 실제 코드를 실행할 때 필요한 
			String.class, List.class 같은 자바 기본 부품들이 컴퓨터 어디에 
			박혀있는지는 전혀 관심이 없습니다.
						
	Project Facets (프로젝트 성격 정의관):
	
		하는 일: 
			이 프로젝트가 단순한 자바 프로그램인지, 
			웹 사이트(Web)인지, 앱인지 프로젝트의 정체성과 스펙을 결정합니다.
			
			만약 내가 Facets 메뉴에서 "나 웹 사이트 만들 거니까 
			Dynamic Web Module 4.0 블록 쓸래!"라고 체크했다고 해봅시다.
			그러면 Project Facets은 즉시 자바 버전을 감시하기 시작합니다. 
			왜냐하면 웹 모듈 4.0 규격을 쓰려면 최소 자바 8 이상이 필수이기 때문입니다.
			
			그런데 내가 Java Compiler나 Build Path를 자바 1.4 같은 구버전으로 낮춰버리면, 
			Project Facets이 가로막아서며 "야! 웹 스펙은 최신인데 자바 버전이 왜 이렇게 낮아? 앞뒤가 안 맞잖아!" 
			하고 프로젝트 전체에 빨간색 X 에러(Facet Error)를 때려버리는 것입니다.
			
			
프로젝트 설정 3곳은 '어디에' 저장될까요?

	이클립스 전체 설정은 내 컴퓨터 깊숙한 곳(Workspace 폴더 내부)에 저장되지만, 
	프로젝트 설정 3곳은 내가 만든 프로젝트 폴더 바로 안에 파일로 직접 저장됩니다.
	지금 보시는 프로젝트 폴더를 윈도우 탐색기로 열어보시면 숨겨진 파일과 폴더들이 있습니다.

	.classpath 파일: 
		내가 설정한 Java Build Path와 Order and Export 정보가 텍스트로 적혀있습니다.
	.settings/org.eclipse.jdt.core.prefs 파일: 
		내가 설정한 Java Compiler 버전과 그 자동 잠금 체크박스 정보가 적혀있습니다.
	.settings/org.eclipse.wst.common.project.facet.core.xml 파일: 
		내가 설정한 Project Facets의 기술 블록 규격들이 적혀있습니다.
		

자세히 파헤쳐 보기

	프로젝트 우클릭 > properties > Java Build Path > Libraries > Jar and class folders on the build path:
		여기에서 Add Library > JRE System Libary 를 선택하면 System libary 에 3개의 선택 상자가 나온다
		
		[] Excution environment: 표준 실행 환경 규격 등록
			JavaSE-1.8 , JavaSE-11 등으로 규격화된 표시가 나온다
			
			[이클립스가 가진 '자바 버전 가이드북']
			- 오직 내가 다운로드한 '이클립스 버전'이 세상에 태어날 때 알고 있던 자바 표준 스펙들의 명단 가이드북이다
			- 이클립스 탄생 이후의 버전은 당연히 모른다(가지고 있지 않다)
			- 내가 최신 JDK를 깔아서 JREs에 등록한 것과는 별개다.
			
			작동방식: 
			이곳에 표시된 표준을 선택하면, 
			내가 전체 JREs에서 설정한(Window>Preferenece>Java>Installed JREs) 
			JRE의 설정에 가서 알아서 해당 버전의 찾아서 연결한다. 없으면 (unbound)표시가 난다
				
			
		[] Alternate JRE: Window > prefernece > Java > Installed JREs 에 등록한 JREs 목록에서 
			이 플젝을 위한 JRE로 바꿀 수 있음.
		
		[] : Window > prefernece > Java > Installed JREs 에 기본 선택된 JREs 환경
