데이터 모델링
	
	- 현실세계 정보를 컴퓨터가 이해하도록 구조화 하는 것
	- 고객의 업무 프로세서 이해 후 모델링 표기법으로 모델링
	- 핵심 특징을 선별, 추상화하고, 합의된 표기법(ERD)로 표현
	- 관련자 간의 원활한 소통을 위한 객관적인 설계도를 만드는 것이 목표

	데이터 모델링의 특징
	
		추상화(Abstraction)
			: 핵심 정보만 선별,불필요한 세부사항 제거 
		
		단순화(Simplification)
			: 복잡한 구조를 약속된 표기법(ERD)으로 쉽게 표현
		
		명확화(Clarity)
			: 누구나 동일하게 이해하도록 명확화
			
	데이터 모델링 최소화 목표
	
		중복 최소화
			: 데이터 중복 방지
			
		비유연성 최소화(유연성 확보)
			: 향후 업무 변경에 쉽게 대응하도록 데이터 구조 유연성 확보
			
		비일관성 최소화(일관성 확보)
			: 데이터간 상호 참조를 명확히 하여 데이터 모순 없는 일관성 확보
	
	데이터 모델링의 3단계
		
		개념적 모델링
			- 핵심 엔터티 도출
			- 기술적 요소 배제한 추상적 단계(추상화 높다)
		
		논리적 모델링
			- 식별자(key,속성) 도출, 릴레이션 정의, 정규화
			- DBMS에 비종속적
			- 재사용성이 높은 단계
		
		물리적 모델링
			- 데이터 타입, 인덱스 등 물리 요소 결정
			- 특정 데이터 베이스 맞게 구축
			- 성능 고려 단계

	데이터 모델링의 3가지 관점(View)

		데이터 
			- (What, 무엇을)
			- 업무 데이터의 종류와 그들간의 구조에 집중하는 관점
			- 구조분석,정적분석 
		프로세스
			- (How, 어떻게)
			- 업부 수행 절차와 흐름에 집중하는 관점
			- 시나리오분석, 도메인 분석, 동적 분석
			
		데이터와 프로세스
			- (Why, 왜)
			- 데이터와 프로세스가 서로 주고받는 영향 관계에 집중하는 관점
			- CRUD 분석
	
	ANSI-SPARC의 3계층 스키마 구조와 데이터 독립성
		
		데이터 독립성: 
			데이터의 저장 구조가 변경되더라도 응용 프로그램은 영향을 받지 않도록 하는 특성.
			
		3계층 스키마(3-level schema)구조
		
			데이터 독립성 확보를 위해 데이터베이스를 3개의 계층으로 분리한 구조
			
				(외부스키마) - (개념스키마) - (내부스키마)
			
			외부스키마
				- (사용자관점)
				- 개인화된 데이터만 보여주는 View
				- 여러개 존재
				
			개념스키마
				- (설계자관점) 
				- 데이터베이스 전체를 정의한 통합된 View
				- 하나만 존재
				
			내부스키마
				- (개발자관점)
				- 데이터의 물리적 저장 구조 정의
			
		데이터 독립성 종류
			
			논리적 독립성 : 개념 스키마 변경 -> 외부 스키마 영향 없음
				
			물리적 독립성 : 내부 스키마 변경 -> (개념스키마,외부스키마) 영향 없음

	ERD 
	
		- 개념: 데이터 모델링 결과를 시각적으로 표현하는 설계도
		
		- 목적: 엔터티와 관계를 도식화하여 관련자 간의 원활한 의사소통을 돕는다
		
		- 표기법: 실무에서는 IE 표기법(까마귀발 표기법)이 널리 사용된다
		
		ERD 작성절차
		
			1.엔터티 도출
			2.엔터티 배치
			3.엔터티 관계 설정
			4.관계명 기술
			5.관계 관계차수 기술
			6.관계 필수/선택(참여도) 여부 기술

			※ 참여도를 5. 넣은 교재도 있다
			잘못된 정보이지만, 워낙 많은 교재가 저렇게 표현한다.
			
	데이터 모델링 고려사항
	
		- 데이터 모델의 독립성
		- 고객 요구사항의 표현
		- 데이터 품질 확보
				
엔터티(Entity)

	- 저장되고 관리되어야 하는 데이터 집합.
	- 데이터베이스 내에서 고유하게 식별 가능한 객체, 개념.
	- 개념, 사건, 장소등의 명사이다.(Thomas Bruce)
	- 엔터티는 자신을 구체적으로 설명하는 속성(Atrribute)으로 구성된다.

	엔터티 개념 정의 (학자 기준 정의)
		Peter Chen, (1976년) : 식별 가능한 사물.
		C.J Date, (1986년) : 데이터베이스 내부에서 식별 가능한 객체.
		James Martin, (1989년) :  정보를 저장할 수 있는 어떤 것
		Thomas Bruce, (1992년) : 정보를 저장할 수 있는 장소,사람,사건,개념,물건 등이다.

	엔터티 도출
	
		고객의 비즈니스 프로세스의 관리되어야 하는 정보에서 추출해야 한다

	엔터티 특징
	
		업무 : 업무에서 관리, 사용 되어야 하는 정보 집합이어야 한다.(당연)
		식별자 : 고유한 식별자(기본키)를 가져야 한다.(당연)
		인스턴스 집합: 2개 이상의 인스턴스가 포함해야 한다.(일반적)
			(1개도 가능하지만, 효율성이 떨어지는 구조)
		속성 : 반드시 1개 이상의 속성을 가져야 한다.(당연)
		관계 : 다른 엔터티와 최소한 1개 이상 관계를 맺어야 한다.(당연)

	엔터티 분류
	
		형태에 따른 분류
			
			유형 엔터티
				- 물리적 형태가 있는 엔터티
				예: (학생, 교수, 강의실)
				
			개념 엔터티
				- 물리적 형태가 없는 엔터티 (개념적 엔터티)
				예: (학과, 강의)
				
			사건 엔터티
				- 업무 수행 의해 발생되는 행위나 사건에 의해 생성되는 엔터티
				예: (수강신청, 성적)

		발생 시점에 따른 분류
		
			기본 엔터티(key entity, basic entity)
				- 업무에 원래부터 존재하는 정보집합
				- 다른 엔터티에 의존하지 않는 독립적 엔터티
				
				예: (학생, 교수, 강의실, 학과)
				
			중심 엔터티(Main Entity)
				- 기본 엔터티로부터 파생된 업무 처리의 중심 역할을 하는 엔터티
				- 데이터 양이 많고, 다른 엔터티과의 관계가 많음
				
				예: (학기, 강의)
				
			행위 엔터티(Active Entity)
				- 2개 이상의 엔터티들의 '행위'에 의해 파생된 엔터티
				- 업무 진행에 따라 내용변경과 데이터 증가 경향이 있다.
				
				예: (수강신청, 성적, 출결)
				
속성(Attribute)

	"엔터티의 구체적인 정보이며, 의미상 더 이상 분해되지 않는 최소한의 데이터 단위"
	
		- 엔터티 구성 항목
		- 인스턴스 구성 요소 
		- 더 이상 분해 안된다

	속성의 특징
		- 업무에서 관리되는 정보
		- 일반적으로 하나의 값만 가진다
		- 주 식별자에게 함수적으로 종속된다.

		좋은 속성
			- 업무와 직접적인 관계가 있어야한다
			- 엔터티에 필수적인 속성만 정의
			
	속성값
	
		"하나의 인스턴스에 특정 속성이 가지는 실제 데이터"
		
	엔터티, 인스턴스, 속성, 속성값 관계 규칙
		
		아래 관계 규칙들은 데이터 모델의 완성도와 효율성을 판단하는 기준이 된다
		
		- 한 개의 엔터티는 2개 이상의 인스턴스를 갖는다.
		- 한 개의 엔터티는 2개 이상의 속성을 갖는다.
		- 한 개의 속성은 1개의 속성값을 갖는다.
		
	속성의 분류
	
		분해 여부에 따른 분류
		
			단일 속성
				- 회원ID, 이름 등
				
			복합 속성
				- 주소는 시,군,동 등으로 분해 된다
				
			다중값 속성
				- 상품리스트
				- 다중값 속성은 엔터티로 분해된다.

		특성에 따른 분류
			
			"속성의 출처와 성격에 따라 분류하는 방식"
			
			기본 속성 
				- 본래의 속성
				- 회원ID,이름 등
				
			설계 속성 
				- 데이터 모델링 과정에성 발생되는 속성
				- 유일값을 가진다
				- 상품코드, 지점코드 등
				
			파생 속성
				- 다른 속성에서 만들어지는 속성
				- 합계, 평균 등

		구성 방식에 따른 분류
		
			"속성이 엔터티 내에서 어떤 역할을 하는지에 따라 분류하는 방식"
		
			- PK(Primary Key, 기본키) 속성:
				엔터티 내의 각 인스턴스를 유일하게 식별하는 속성
				
			- FK(Foreign Key, 외래키) 속성:
				다른 엔터티 PK(기본키)를 참조하여 참조하여 엔터티 간의 관계를 연결하는 속성
				
			- 일반 속성: PK,FK 가 아닌 나머지 속성 
						
	도메인
		하나의 속성이 가질 수 있는 값의 범위와 규칙을 정의한 것
		
		도메인 설정 항목
		- 데이터 타입(Type): 문자, 숫자, 날짜 등
		- 크기(Size): 문자의 최대 길이 또는 숫자의 전체 자릿 수 등
		- 허용값(Check): '남,여' 또는 '0 >' 조건 등
		- NULL 허용 여부: 값을 비워도 되는지 여부
		- 기본값(Default): 값을 생략했을때 자동으로 입력될 기본값
		
			
관계(relationship)

	엔터티와 엔터티 사이의 논리적인 연관성을 의미
	
	관계의 종류
	
		존재적 관계
			- 엔터티 간의 소속이나 포함 관계
			('학생'은 '학과'에 소속 관계)
			
		행위적 관계
			- 엔터티 간의 행위나 사건 표현 관계			
			('학생'은 '강의'를 수강한다)

	관계 표기법
	
		관계명(Membership)
			두 엔터티 간의 행위나 상태를 '수강한다','소속된다' 와 같은 동사로 표현
			
		관계 차수(Cardinality) 
				
			두 엔터티 간에 연결될 수 있는 데이터 건수의 규칙을 의미합니다.
			
			- 최대 기수성 (Maximum Cardinality) : 
				"최대 몇 개까지 연결될 수 있는가?" (1 또는 Many)
				
			- 최소 기수성 (Minimum Cardinality) : 
				"최소한 몇 개는 연결되어야 하는가?" (0 또는 1)				
		
		1. 최대 기수성에 따른 관계의 종류 
		
			최대 기수성이 1이냐 Many(N, M)이냐에 따라 관계의 형태가 분류됩니다.
			
			- 일대일 (1:1) 관계
				• 완전 1:1 : 양쪽 모두 반드시 데이터가 존재해야 하는 필수 관계
				• 선택적 1:1 : 한쪽이나 양쪽 데이터가 없어도 되는 관계 (예: 사원과 군필 정보)
				
			- 일대다 (1:N) 관계
				• 데이터베이스에서 가장 흔하고 이상적인 표준 관계 (예: 부서와 사원)
				
			- 다대다 (M:N) 관계
				• 문제점 : 이 상태로 테이블을 만들면 중복 데이터와 무차별 결합(카테시안 곱)이 발생합니다.
				• 해결책 : 물리 체계에서는 그대로 구현할 수 없으므로, 
				중간에 연결 테이블을 두어 1:N 또는 1:1 관계로 해소(분해)해야 합니다.

			
		2. 관계선택사양(Optionality) == '최소 기수성'
			
			'최소 기수성'을 다르게 부르는 말로, 관계의 필수/선택 여부를 나타냅니다
		
			• 개념 : 한 엔터티의 데이터가 존재할 때 상대 엔터티의 데이터가 
			반드시 있어야 하는지(필수), 없어도 되는지(선택)를 결정합니다.
			
			• 까마귀발(Crow's Foot) 표기법
				- 필수 (Mandatory) : │ (실선 기호) → 최소 기수성 1을 의미
				- 선택 (Optional) : ○ (원 기호) → 최소 기수성 0을 의미	

엔터티 식별자(Entity Identifier)
	
	식별자(Identifier)
	
		- 인스턴스를 유일하게 구분할 수 있는 속성 또는 속성들의 집합
	
	주 식별자와 보조 식별자
	
		주 식별자(Pramary Identyfier)
		
			- 후보 식별자들 중에서, 엔터티를 대표하는 핵심 식별자
			- 다른 엔터티와 관계를 맺는 기준
			- 기본키
		
		보조 식별자(Alternate Identifier)
			- 주 식별자가 아닌 나머지 후보 식별자들
			- 대체키
		
	식별자의 4대 특성
	
		좋은 식별자는 다음의 4가지 특징을 만족해야 한다.
		
		- 유일성
			모든 인스턴스를 유일하게 식별해야 한다.
		- 최소성
			유일성을 만족하는 최소한의 속성으로 구성되어야 한다.
			(식별하는 데 있어서 더 이상 뺄 수 없는 최적의 멤버 조합이면 최소성 만족)
		- 불변성
			식별자의 값은 한번 정해지면 변하지 않아야 한다.
		- 존재성
			주 식별자는 NULL값을 가질 수 없으며, 반드시 존재해야 한다.
	
	식별자 분류
				
		대표성 여부
			주 식별자: 기본키(PK)
			보조 식별자: 대체키(AK)
			
		스스로 생성되었는지 여부
			내부 식별자: 주문 엔터티의 (주문번호)
			외부 식별자: 주문 상세 엔터티의 (주문번호 + 상품번호)
			
		단일 속성 여부 (속성 수 기준)
			단일 식별자: 학생 엔터티의 (학번)
			복합 식별자: 수강신청 엔터티의 (학번 + 과목코드)
			
		대체 여부 
			본질 식별자: 강의 엔터티의 (학과명 + 과목명 + 분반)
			인조 식별자: 강의 엔터티의 (강의 코드)
		
		------------- 비슷한 식별자 비교하기
		• 내부 식별자: 
			상속받지 않고, 
			내 테이블에 필요해서 처음부터 새로 판 식별자
		• 인조 식별자: 
			원래 있던 본질 식별자가 너무 복잡하니까, 
			더 단순하게 만들려고 억지로 새로 판 식별자
		-------------
		
	식별자 관계, 비식별자 관계
	
		강한 개체 : 독립적 개체 (부모 엔터티)

		약한 개체 : 강한 개체의 존재에 의존되는 개체 (자식 엔터티)
		
		식별자 관계 (identifying Relationship) 
			- 부모 엔터티 기본키를 자식 엔터티 기본키 일부로 포함한 관계.
			- 실선 표현
			
		비식별자 관계 (Non-identifying Relationship)
			- 부모 엔터티 기본키를 자식 엔터티 일반 컬럼(FK)에 포함한 관계.
			- 점선 표현
			
		식별자 관계와 비식별자 관계 비교
			
			<식별자 관계>
			핵심: 부모 PK -> 자식 PK의 일부
			종속성: 강함 (부모 없이 존재 불가)
			표기법: 실선
			
			<비식별자 관계>
			핵심: 부모 PK -> 자식 엔터티 일반 속성(FK)
			종속성: 약함 (독립적 존재 가능)
			표기법: 점선

무결성 제약

	개체 무결성: PK (중복 금지, Null 금지)
	
	고유 무결성: UNIQUE 제약 조건 (중복 금지, Null 허용)
	
	참조 무결성: FK (중복 허용, Null 허용)
		• CASCADE: 
			부모가 지워지면 자식도 연쇄 삭제
		• SET NULL: 
			부모가 지워지면 자식의 외래키 값을 NULL로 변경
		• RESTRICT / NO ACTION: 
			자식 데이터가 남아있으면 부모 데이터 삭제 금지(거부)

	도메인 무결성: CHECK, TYPE, DEFAULT
	
	사용자 정의 무결성: Trigger, 사용자 정의 함수 등

🗂️ 식별자(키) 상세 종류 

	[대전제] "외래키를 제외한 모든 식별 키는 데이터 중복이 절대 불가능하다!"

	■ 고유키 (큰 개념 순서대로)		
	  1. 슈퍼키(Super key): 유일성 만족, 최소성 무시 (가장 넓은 개념)
	  2. 후보키(Candidate key): 유일성과 최소성을 만족하는 키 (더 이상 뺄 속성이 없는 정예 상태)
	  3. 대체키(Alternate key): 후보키 - 기본키 = 대체키 (기본키 경쟁에서 탈락한 키)
	  4. 기본키(Primary key): 
		- 후보키 중 엔터티를 대표할 수 있는 유일한 키
		- (대표성, 유일성, 최소성, 불변성, 존재성) 모두 만족하는 키
		- 개체 무결성
		
	  <NULL 허용 여부>
	  - 수퍼키: NULL 허용 (잉여 속성에 NULL이 섞여도 식별만 되면 됨)
	  - 후보키, 대체키: NULL 조건부 허용 (필수 데이터면 불가, 선택 데이터면 허용)
	  - 기본키: NULL 절대 불가 (NOT NULL - 개체 무결성 제약)		

	■ 외래키(Foreign key) - [확장 개념]
	  - 다른 Entity의 기본키를 참조하여 '참조 무결성'을 유지하기 위한 키
	  - 참조 무결성
		  - NULL 허용 (부서가 아직 없는 신입사원 등 선택적 관계일 때)
		  - 중복 허용 (1:N 관계가 기본이므로 중복이 자연스러움)
		    ※ 단, 테이블 간의 관계가 '1:1 관계'일 때는 
		    예외적으로 중복 불가 (Unique 제약 추가)
