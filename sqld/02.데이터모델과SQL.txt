정규화
	
	개념
		테이블 데이터의 중복성 최소화, 일관성, 정확성을 유지하도록 정리하는 과정
		(데이터 중복으로 인한 이상현상 예방)

	이상 현상(Anomaly)
		
		삽입 이상: 불필요한 데이터가 없으면 필요한 데이터를 삽입하기 어려움
		
		갱신 이상: 중복된 데이터를 일부만 수정해 불일치 발생
		
		삭제 이상: 한 데이터를 삭제하면서 필요한 다른 정보까지 사라짐
		
	함수 종속성 (函數 從屬性)
	
		함수 종속성이란 어떤 값이 다른 값에 의해 결정되는 성질
		
			A -> B
			
			: A에 의해 B가 결정
			(A:결정자 , B:종속자)
			
		종속 방식에 따른 구분
		
			완전 함수 종속
				
				(학번, 과목코드) → 성적
				
				: 학번,과목코드 두개를 모두 알아야 '성적'이 결정된다.
				
			부분 함수 종속
			
				(학번, 과목코드) → 학생명
				
				: 부분인 '학번'만 알아도 '학생명' 이 결정된다
				
			이행(移行) 함수 종속

				사원번호 → 부서번호 → 부서명

				: '사원번호'가 '부서번호'를 결정하고,'부서번호'가 '부서명'을 결정한다.

				즉, '사원번호'가 '부서번호'를 거쳐 간접적으로 '부서명'을 결정한다.
				(직접 결정하는 관계가 연쇄적으로 이어져 간접적인 결정 관계 생김)
			     
			-------------
			완전: 전체를 알아야 결정
			부분: 일부만 알아도 결정
			이행: 중간을 거쳐(이행) 결정
			-------------
		
		속성 포함 여부에 따른 구분
		
			자명(自明) 함수 종속
				
				오른쪽 속성이 왼쪽 속성 집합에 포함
					(A, B) → A
							
			비자명(非自明) 함수 종속
				
				오른쪽 속성이 왼쪽 속성 집합에 포함되지 않음
					A → B				
			 

	정규화 단계
	
		제1정규화(1NF): 원자값
			
			- 속성값을 원자값으로 구성
			
		제2정규화(2NF): 부분 함수 종속성 제거
			
			- 복합 후보키의 일부에만 종속되는 비주요 속성 제거
			
		제3정규화(3NF): 이행 함수 종속 제거
			
			- 기본키가 아닌 속성 간의 이행 함수 종속 제거
			
		BCNF: 모든 비자명 함수 종속 결정자가 슈퍼키가 되도록 구성
			
			- 모든 비자명 함수 종속 X → Y에서 결정자 X는 슈퍼키여야 한다.
	 		- 시험에서는 '후보키'로 설명하는 경우도 있음(엄밀히는 '슈퍼키')
			
		제4정규화(4NF): 다치(다중값) 종속 제거
			
			- 독립적인 다중 값으로 발생하는 중복 제거
			
		제5정규화(5NF): 조인 종속 제거
			
			- 불필요한 조인 종속 제거

반정규화 (De-Normalization)
			
	- 조인을 줄이거나 중복 데이터를 추가하여 성능을 향상 시키는 기법
	- 조회 성능은 향상하나, 데이터 모델의 유연성은 낮아진다.

	반정규화 절차
		
		- 대상 조사 및 검토
		- 다른 방법 검토
		- 반정규화 수행
		
	테이블 반정규화
		
		테이블 병합
			
			- 1:1 관계 병합: 1:1 관계 테이블을 하나로 통합
			- 1:M 관계 병합: 1쪽 테이블을 없애고 M쪽 테이블에 포함하여 통합	
			
		테이블 분할
		
			- 수직 분할 : 컬럼 분할
			- 수평 분할 : row의 특정 값을 기준으로 분할
													
		테이블 추가
		
			- 중복 테이블 추가: 원격 서버의 테이블을 현재 서버에 복제 추가
			- 통계 테이블 추가: 미리 계산된 통계테이블 추가
			- 이력 테이블 추가: 데이터의 변경내역만을 관리하는 테이블 추가
			- 부분 테이블 추가: 자주 사용하는 일부 데이터용 테이블 추가
			
	컬럼 반정규화
	
		- 중복 컬럼 추가: 다른 테이블 컬럼을 현재 테이블에 중복 추가하여 조인을 줄인다
		- 파생 컬럼 추가: 조회시 필요한 계산 결과를 미리 별도의 컬럼에 추가
		- 이력 컬럼 추가: 이력 데이터의 조회 성능을 높이기 위해 이력 관련 컬럼을 추가
		
	관계 반정규화
		원래 모델에 없던 중복된 관계를 추가(성능을 위해)
		예:(학생->학과-교수) 관계를 (학생->교수) 관계를 추가해서 성능 향상.
		
분산데이터베이스
	
	분산데이터베이스 투명성 종류
		분할 투명성
		위치 투명성
		지역 사상 투명성
		중복 투명성
		장애 투명성
		병행 투명성

	분산데이터베이스 설계 방식
		상향식 설계 방식
			지역 스키마 -> 전역 스키마
		하향식 설계 방식
			전역스키마 -> 지역 사상 스키마

	분산데이터 베이스 장단점
		장점
			- 신뢰성,가용성 높음
			- 병렬처리로 빠른 응답
			- 용량 확장 용이
		단점
			- 관리와 통제 어려움
			- 보안 관리 어려움
			- 데이터 무결성 관리 어려움
			- 설계 복잡
