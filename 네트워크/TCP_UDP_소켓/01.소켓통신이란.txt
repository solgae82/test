
	소켓 통신(Socket Communication)은 네트워크로 연결된 두 컴퓨터(서버와 클라이언트)가 
	실시간으로 양방향 데이터를 주고받기 위해 연결을 유지하는 방식입니다
	

1. 소켓(Socket)이란?

	• 정의: 
		응용프로그램(소프트웨어)이 네트워크를 통해 
		데이터를 내보내거나 받기 위해 거치는 
		소프트웨어적 연결 창구(인터페이스)입니다.
	
	• 구성요소: 소켓은 프로토콜, IP 주소, 포트 번호(Port)로 정의됩니다.
		• 프로토콜: 통신 규칙 (주로 TCP 또는 UDP 사용)
		• IP 주소: 네트워크상의 컴퓨터를 찾는 고유 주소
		• 포트 번호: 컴퓨터 내부에서 동작하는 특정 프로그램을 구분하는 번호
	
	(예시) : TCP, 192.168.0.10, 8080번 포트에서 요청을 기다리는 소켓
	
2. 소켓 통신의 주요 특징

	• 실시간 양방향 통신: 
		클라이언트뿐만 아니라 서버 쪽에서도 언제든 데이터를 먼저 보낼 수 있습니다.
	
	• 연결 유지 (Connection-oriented): 
		한번 연결이 되면 통신을 종료할 때까지 계속 연결 상태를 유지합니다.
	
	• 높은 자원 소모: 
		연결을 계속 붙잡고 있어야 하므로, 
		불특정 다수가 접속하는 일반 웹사이트 환경보다는 리소스 소모가 큽니다.
	
	• 활용 사례: 
		실시간 채팅, 온라인 게임, 주식 시세 조회, 실시간 스트리밍 등


3. 소켓 통신의 대표적인 두 가지 방식 (프로토콜)

	• 스트림 소켓 (TCP 방식)
		• 데이터를 끊김 없이 순서대로 안전하게 전달합니다.
		• 신뢰성이 높아서 채팅이나 파일 전송 등에 주로 쓰입니다.
	
	• 데이터그램 소켓 (UDP 방식)
		• 연결 절차 없이 빠르게 데이터를 전송합니다.
		• 일부 데이터가 유실되더라도 실시간 속도가 중요한 온라인 게임이나 영상 스트리밍에 주로 쓰입니다.
		
------------------- 소켓 작동과 식별 방법 관점 두가지

1. 소켓을 생성하고 대기할 때 (종단점 관점, 큰틀)

	컴퓨터가 네트워크 통신을 하기 위해 문(Door)을 열어두는 단계입니다. 

	• 프로토콜: TCP 또는 UDP
	• IP 주소: 데이터가 찾아올 컴퓨터의 주소
	• 포트 번호: 컴퓨터 안에서 해당 데이터를 처리할 프로그램(프로세스)의 번호
	
	이 세 가지가 합쳐져 네트워크상의 유일한 종단점(Endpoint)을 이룹니다.

	(예시) : TCP, 192.168.0.10, 8080번 포트에서 요청을 기다리는 소켓


2. 실제 연결이 맺어지고 통신할 때 (커넥션 관점)

	TCP: 
		TCP 통신에서는 서버의 특정 포트(예: 80번 웹 서버 포트) 하나에 
		수많은 클라이언트가 동시에 접속합니다.
		
		만약 서버가 (프로토콜 + IP + 포트 번호)로만 소켓을 구별한다면, 
		여러 클라이언트에서 들어오는 데이터가 뒤섞이게 됩니다. 
		
		그래서 실제 TCP 연결(Connection)이 수립되면, 
		운영체제는 내부적으로 총 4가지 정보(4-tuple)를 조합하여 소켓을 식별하고 
		데이터를 정확한 클라이언트에게 전달합니다.
		
			• 출발지 주소 정보: 클라이언트 IP + 클라이언트 포트 번호
			• 목적지 주소 정보: 서버 IP + 서버 포트 번호
			
		이 덕분에 서버는 같은 포트(8080)를 열고 있더라도, 
		접속한 클라이언트마다 서로 다른 소켓을 생성해 1:1로 안전하게 통신할 수 있습니다
	
	UDP:
		
		UDP는 연결을 맺지 않는 비연결형(Connectionless) 프로토콜입니다. 
		따라서 클라이언트가 아무리 많이 접속해도 서버에는 새로운 소켓이 생성되지 않고, 
		처음에 열어둔 단 하나의 소켓(2-Tuple: 목적지 IP + 목적지 포트)으로 모든 통신을 처리합니다.

		🧩 UDP 소켓의 식별 정보 (2-Tuple)

		TCP는 4가지 정보(출발지 IP/포트 + 목적지 IP/포트)로 소켓을 식별했지만, 
		UDP 소켓은 오직 2가지 정보만 보고 나에게 온 데이터인지 확인합니다.
		
			• 목적지 IP 주소: 데이터가 도착한 컴퓨터의 주소
			• 목적지 포트 번호: 컴퓨터 안에서 이 데이터를 받을 UDP 프로그램의 번호

		운영체제는 네트워크선으로 들어온 UDP 패킷의 목적지 IP와 포트가 서버에 열려있는 UDP 소켓과 일치하면, 
		출발지가 누구든 상관없이 전부 그 하나의 소켓 안으로 던져 넣어 줍니다.
		
		
	
	🆚 커넥션 관점에서의 TCP vs UDP 최종 비교


	구분		|TCP (연결형)					|UDP (비연결형)
	-------------------------------------------------------------------------------------
	소켓 식별 기준	|4-Tuple					|2-Tuple
			|(출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트)	|(목적지 IP, 목적지 포트) 
	-------------------------------------------------------------------------------------
	통신 상태		|통신 전 악수(3-Way Handshake)를 통해		|연결 상태라는 것이 없음. 
			|연결 상태(ESTABLISHED)를 유지함.			|패킷을 던지면 끝인 독립적인 데이터그램 형태.		
	-------------------------------------------------------------------------------------
	클라이언트 추가 시	|운영체제가 해당 클라이언트 전용 소켓을 새로 생성함.	|소켓 추가 없음. 
			|						|기존 하나의 소켓으로 패킷만 추가로 받음.
	-------------------------------------------------------------------------------------
