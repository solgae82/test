하나의 서버(포트 8080)에 두 명의 클라이언트(A, B)가 동시에 접속하는 상황을 기준으로 설명
-------------------

TCP의 실제 통신 과정: "철저한 예약제 1:1 대면 상담"

	TCP는 연결 지향형(Connection-oriented)입니다. 

	데이터를 보내기 전에 반드시 "우리가 통신할 준비가 되었는가?"를 확인하고, 
	연결이 완료되면 클라이언트마다 독립된 통신 선로(전용 소켓)를 깔아줍니다.

1단계: 서버의 대기 (Listen)

	• 서버는 TCP 0.0.0.0:8080 형태로 소켓을 열고, 클라이언트의 요청을 기다립니다. 
	이 소켓을 '문지기 소켓(Listening Socket)'이라고 합니다.

2단계: 연결 수립 (3-Way Handshake)

	• 클라이언트 A가 서버에 접속 요청(SYN)을 보냅니다.
	
	• 서버와 클라이언트 A가 총 3번의 대화를 주고받으며 서로의 상태를 확인합니다.
	
	• 핵심 체인지: 
		
		연결이 성공하는 순간, 운영체제는 문지기 소켓 외에 클라이언트 A 전용 소켓을 
		컴퓨터 내부(커널)에 새로 만들어 줍니다.
		
		• A 전용 소켓 식별자: [출발지: A의 IP/포트] ↔ [목적지: 서버 IP:8080]
	
	• 이어서 클라이언트 B가 접속하면, 똑같이 3-Way Handshake를 거친 후 
	클라이언트 B 전용 소켓이 또 하나 만들어집니다.
	
		• B 전용 소켓 식별자: [출발지: B의 IP/포트] ↔ [목적지: 서버 IP:8080]

3단계: 실제 데이터 송수신 (Data Transfer)

	• 클라이언트 A가 데이터를 보낼 때: 데이터 패킷에 [출발지: A, 목적지: 서버:8080]을 적어 보냅니다.
	
	• 서버 운영체제의 역할: 
		
		패킷의 출발지가 'A'인 것을 보고, 수많은 소켓 중 
		정확히 'A 전용 소켓'의 버퍼(Buffer)에만 데이터를 넣어줍니다. 
		
		서버 프로그램은 이 A 전용 소켓에서 데이터를 꺼내 읽으므로, B의 데이터와 섞일 일이 절대 없습니다.
	
	• 안전장치: 
		서버가 데이터를 잘 받으면 클라이언트 A에게 "잘 받았다"는 확인 신호(ACK)를 보냅니다. 
		만약 ACK가 안 오면 클라이언트 A는 데이터를 다시 보냅니다(재전송).

4단계: 연결 종료 (4-Way Handshake)

	• 통신이 끝나면 서로 "이제 연결 끊자"라고 4번에 걸쳐 신호를 주고받은 뒤, 
	생성되었던 전용 소켓들을 완전히 파괴합니다.

-------------------
• TCP는 OS가 배달원입니다. 
OS가 패킷의 4-tuple(출발지 IP/포트, 목적지 IP/포트)을 보고 정확한 전용 소켓 방으로 직접 배달해 줍니다. 
개발자는 그냥 내 앞에 차려진 방(소켓)에서 데이터를 편하게 읽기만 하면 됩니다.
