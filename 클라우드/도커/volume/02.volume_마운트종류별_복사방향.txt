
<volume 구분별  복사 방향>

	볼륨 마운트: 호스트 빈볼륨 <- 연결된 컨테이너 내부 데이터 
	바인드마운트:  호스트 경로 ->  연결된 컨테이너 내부 데이터

이 부분이 헷갈려서 실무에서 데이터를 날려 먹는 실수를 많이 합니다

-------------------

1. 볼륨 마운트: 컨테이너 ➡️ 호스트 볼륨 (초기 복사 메커니즘)

	작동 방식: 
		도커가 관리하는 새 빈 볼륨을 컨테이너에 처음 연결하면, 
		컨테이너 내부 타깃 폴더에 원래 있던 파일들이 호스트의 빈 볼륨 영역으로 
		먼저 복사(Copy)됩니다.

	이유: 
		도커가 볼륨을 "컨테이너의 데이터를 안전하게 보존하기 위한 전용 주머니"로 
		인식하기 때문입니다.
	
	실무 예시: 
		mysql 이미지는 내부에 기본 설정 파일과 기초 DB 구조를 가지고 있습니다. 
		이를 새 도커 볼륨에 마운트하면, 컨테이너가 켜지면서 그 기초 파일들을 
		도커 볼륨 폴더(/var/lib/docker/volumes/.../_data)로 채워 넣어 줍니다.
	
2. 바인드 마운트: 호스트 경로 ➡️ 컨테이너 (덮어쓰기 메커니즘)
	
	작동 방식: 
		호스트의 특정 폴더를 연결하면, 컨테이너 내부 폴더에 뭐가 들어있든 상관없이 
		호스트 폴더의 상태로 그대로 덮어써 버립니다(Overwrite). 
		만약 호스트 폴더가 비어 있다면 컨테이너 내부 폴더도 빈 폴더처럼 보이게 됩니다.

	이유: 
		바인드 마운트는 호스트의 파일 시스템을 컨테이너에 
		"그대로 투과해서 보여주는 거울(Pointer)" 역할을 하기 때문입니다.

	실무 예시: 
		소스 코드가 들어있는 호스트 폴더를 바인드 마운트하면, 
		컨테이너는 원래 자신이 가지고 있던 기본 코드 대신 사용자가 호스트에서 작성한 코드를 
		그대로 바라보고 실행하게 됩니다.
		
3. 한 줄 요약 구조도

	볼륨 마운트 (컨테이너 중심 보호)
	
		[컨테이너 내부 데이터] ──(최초 1회 자동 복사)──> [도커가 만든 빈 볼륨]
		
	바인드 마운트 (호스트 중심 강제)
		
		[사용자의 호스트 폴더 (빈 폴더)] ──(강제 동기화/덮어쓰기)──> [컨테이너 내부 데이터 은폐]
		
-------------------

이 특성 때문에 "DB 같은 기성 이미지는 볼륨 마운트"를 해야 초기 데이터가 깨지지 않고, 
"내가 코드를 고쳐야 하는 개발 환경은 바인드 마운트"를 해야 호스트의 수정본이 컨테이너에 바로 반영됩니다
