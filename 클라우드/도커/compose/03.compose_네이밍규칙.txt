
1. 이미지명,컨테이너명 생성 규칙

	도커 컴포즈는 기본적으로 [명령을 내리는 현재 디렉토리명]-[서비스명] 구조로 
	이미지나 컨테이너 이름을 자동으로 생성합니다.
	
	실제 예시:
	만약 /home/dong 디렉토리 안의 docker-compose.yml에서 
	서비스 이름을 db와 app으로 정의하고 빌드(docker compose build)했다면, 
	실제 생성되는 이미지 이름은 다음과 같습니다.
	
		(db 서비스) => dong-db:latest
		(app 서비스) => dong-app:latest
	
2. 복원 및 실행시 디렉토리 규칙
	
	docker load 할 때: 
		
		아무 폴더(예: /root, /tmp)에서나 명령을 내려도 이미지 파일(dong-db, dong-app)은 
		도커 엔진에 원래 이미지 이름 그대로 완벽하게 복원됩니다.
		
	새 서버에서 docker compose up 할 때 (⚠️ 중요):
		
		새 서버로 docker-compose.yml 파일을 옮긴 뒤, 
		만약 폴더 이름을 dong이 아니라 /home/hong으로 만들고 
		그 안에서 실행하면 도커 컴포즈는 자동으로 hong-db라는 이미지를 찾기 시작합니다.
		
		이때 이미 복원된 이미지는 dong-db이기 때문에, 컴포즈는 
		"어? hong-db 이미지가 없네?"라며 에러를 내거나 
		인터넷에서 새로 다운을 시도하게 됩니다.
	
	
3. 실무 해결책
	
	이미지명과 컨테이너명의 원치 않는 이름으로 자동 생성되는 것을 막으려면 아래 두가지 방법중 하나를 선택해야한다.
	
	방법 A (직관적인 방법): 
		새 서버에서도 똑같이 /home/dong 이라는 이름의 폴더를 만들고, 
		그 안으로 docker-compose.yml을 넣은 뒤 docker compose up -d를 실행합니다.
		
	방법 B (실무 추천 - 강제 네이밍): 
		애초에 docker-compose.yml 파일 안에 폴더 이름에 영향받지 않도록 고정 이미지명을 적어두는 것입니다.

		./docker-compose.yml
		
		version: "3.7"
		services:
		  db:
		    # 💡 이렇게 image 명을 명시하면, 어느 폴더에서 실행하든 항상 이 이름으로 빌드/인식합니다.
		    image: my-fixed-db:latest 
		    build: ./db_dir
		    ..
