[Docker] 실무에서 Dockerfile과 Docker Compose를 연동하는 이유

	오픈소스 프로젝트나 실무 협업용 GitHub 저장소를 보면 
	항상 Dockerfile과 docker-compose.yml이 나란히 존재합니다. 

	두 도구는 역할이 명확히 다르며, 함께 연동될 때 가장 강력한 시너지를 냅니다.

1. 두 도구의 명확한 역할 분담

	Dockerfile (이미지 빌드 레이어)

		역할: 
			우리 회사/개인의 커스텀 애플리케이션 이미지를 만드는 설계도입니다.
		내용: 
			앱이 돌아갈 기본 환경 세팅(OS, 언어 버전, 패키지 설치, 소스코드 복사 등)을 
			정적으로 기록합니다.

	docker-compose.yml (실행 및 인프라 조립 레이어)

		역할: 
			커스텀 이미지와 기성 이미지(MySQL, Redis 등)를 한데 묶어 
			최종 서비스를 조립하고 구동하는 도구입니다.
			
		내용: 
			실제 앱이 가동될 때 필요한 동적 설정
			(환경 변수 주입, 포트 개방, 데이터베이스 연결, 볼륨 마운트 등)을 담당합니다.


2. docker commit 대신 Dockerfile을 연동하는 결정적 이유

	수동으로 컨테이너를 고치고 docker commit으로 이미지를 만들어 컴포즈에 올려도 작동은 합니다. 
	
	하지만 실무에서 이 방식을 절대 쓰지 않고 
	Dockerfile 연동 빌드 전략을 취하는 이유는 다음과 같습니다.

	히스토리(이력) 추적 불가: 
		commit 이미지는 내부가 어떻게 설정되었는지 기록이 남지 않는 블랙박스가 됩니다. 
		반면 Dockerfile은 인프라가 코드로 문서화되어 관리가 쉽습니다.

	이미지 용량 최적화: 
		수동 세팅 과정에서 발생한 다운로드 캐시, 임시 파일 등이 commit 이미지에 
		그대로 포함되어 용량이 비대해집니다. 
		
		Dockerfile은 필요한 레이어만 깔끔하게 빌드하여 용량을 최소화합니다.


3. [실전 예제] Dockerfile과 docker-compose.yml 연동하기

	실전에서는 컴포즈를 실행할 때, 외부에서 이미지를 다운받는 것이 아니라 
	내 로컬의 Dockerfile을 읽어서 이미지를 실시간으로 빌드하도록 설정합니다.

	1) Dockerfile (내 커스텀 파이썬 앱 설정)
	
		FROM python:3.11
		WORKDIR /app
		COPY . .
		RUN pip install -r requirements.txt
		CMD ["python", "main.py"]

	2)  docker-compose.yml (실전 연동 예제)
	
		version: "3.7"

		services:
		  # 1. 우리 회사의 커스텀 파이썬 웹 앱 서비스
		  web-app:
		    # 💡 [핵심] 외부 이미지를 다운받지 않고, 현재 디렉토리('.')의 Dockerfile을 읽어 이미지를 직접 빌드합니다.
		    build: .
		    # (선택) 빌드되어 생성될 이미지 이름을 내 마음대로 고정하고 싶을 때 명시합니다.
		    image: my-custom-python-app:v1 
		    ports:
		      - "8000:8000"
		    environment:
		      - DB_HOST=db-server # 아래 정의된 db-server 서비스와 자동 연동
		      - APP_ENV=production
		    depends_on:
		      - db-server # DB 컨테이너가 먼저 켜진 후 웹 앱이 켜지도록 순서 보장

		  # 2. 오픈소스 기성 이미지 (MySQL 데이터베이스)
		  db-server:
		    image: mysql:8.0 # 💡 기성 이미지는 build 대신 image 명을 바로 적어 다운로드합니다.
		    restart: always
		    volumes:
		      - ./db_data:/var/lib/mysql
		    environment:
		      MYSQL_ROOT_PASSWORD: "password123"
		      MYSQL_DATABASE: "mydatabase"

💡 실전 운영 명령어 정리

	이 구조로 세팅된 디렉토리에서는 단 한 줄의 명령어로 이미지 빌드부터 컨테이너 조립 및 실행까지 완전히 자동화됩니다.

	# 1. Dockerfile을 읽어 이미지를 빌드한 후, 컨테이너들을 백그라운드에서 일괄 실행
	docker compose up -d --build

	# 2. 소스코드가 바뀌어서 이미지만 새로 굽고 싶을 때
	docker compose build

	# 3. 전체 인프라 깔끔하게 종료 및 삭제
	docker compose down
