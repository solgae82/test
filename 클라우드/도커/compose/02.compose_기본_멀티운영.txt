[Docker] 빌드와 실행의 분리: 멀티 Docker Compose 운영법

	도커 컴포즈는 기본적으로 현재 디렉토리의 docker-compose.yml을 참조하지만, 
	-f (file) 옵션을 사용하면 목적에 따라 빌드용과 실행용 설정 파일을 
	완벽히 분리하여 관리할 수 있습니다.

1. 왜 파일을 분리해야 할까요?
	
	빌드 단계: 
		소스 코드를 복사하고, 패키지를 다운받아 
		기본 이미지(Base Image)를 굽는 과정이 중심입니다.
	
	실행 단계: 
		가동되는 서버 환경(개발, 테스트, 운영)에 맞게 환경 변수를 주입하고, 
		포트를 열고, 볼륨을 연결하는 과정이 중심입니다.
	
	오버라이딩(덮어쓰기) 규칙: 
		도커는 나중에 정의한 규칙이 이전 규칙을 덮어쓰는 특성이 있습니다. 
		따라서 빌드 파일로 기본 뼈대를 만들고, 
		실행 파일로 실제 운영 환경에 맞는 값을 덮어씌워 컨테이너를 생성합니다.

2. [실전] 목적별 파일 구성 및 명령어 흐름

	1단계: 이미지 빌드 및 배포 (Build & Push)
		
		이미지를 구워내고 저장소(Docker Hub)에 올리는 단계입니다. 
		파일명이 다를 때는 반드시 -f 옵션을 붙여야 합니다.

		(예제)
		# 1. 빌드 전용 컴포즈 파일을 지정하여 이미지 빌드
		docker compose -f docker-compose-build.yml build

		# 2. 빌드된 이미지를 도커 허브 등 원격 저장소에 업로드
		docker compose -f docker-compose-build.yml push

		
	 2단계: 컨테이너 최초 생성 및 실행 (Up & Down)
	 
		이미지 빌드가 끝난 후, 실제 서비스를 가동하는 단계입니다. 
		파일명이 기본값인 docker-compose.yml이라면 -f 옵션을 생략할 수 있습니다.

		(예제)
		# 1. 기본 docker-compose.yml을 읽어와 환경변수 등을 반영 후 백그라운드 구동
		docker compose up -d

		# 2. 서비스 종료 및 컨테이너, 네트워크 일괄 삭제
		docker compose down

	 3단계: 가동 중인 서비스 운영 (Stop & Start)
	 
		up 명령어로 컨테이너가 한 번 생성된 이후에는, 구조를 바꾸지 않는 한 
		컨테이너를 굳이 삭제(down)할 필요 없이 가동 상태만 제어합니다.
		
		(예제)
		docker compose stop     # 컨테이너 일시 중지
		docker compose start    # 중지된 컨테이너 다시 시작 (기본 백그라운드)
		docker compose restart  # 컨테이너 재시작

		💡 핵심 포인트: 
		컴포즈 환경에서는 개별 컨테이너 명령어(docker stop/start)를 개별적으로 쓸 일이 거의 없습니다. 
		docker compose 명령어가 전체 인프라를 통제하는 기준이 됩니다.
		
💡 한 줄 요약 및 실무 팁

	docker-compose-build.yml로 기본 이미지를 안전하게 빌드하고, 
	docker-compose.yml로 운영 환경에 맞는 변수와 설정을 덮어써서 실행합니다.
	
	반드시 해당 파일들이 위치한 디렉토리에서 명령어를 실행해야 도커가 경로를 잃어버리지 않습니다.
