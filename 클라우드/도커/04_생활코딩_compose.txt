[Docker] CLI 수동 실행 vs Docker Compose 연동 비교 및 정리

도커 컴포즈(Docker Compose)는 복잡한 멀티 컨테이너 환경을 docker-compose.yml 파일 하나로 정의하고, 
단일 명령어로 일괄 제어하는 컨테이너 오케스트레이션 도구입니다.

1. [방법 A] CLI 수동 등록 과정
	
	매번 긴 명령어를 입력해야 하며, 컨테이너 간의 실행 순서와 네트워크 연결을 사용자가 직접 관리해야 합니다.
	
	# 1. 컨테이너 간 통신을 위한 전용 네트워크 생성
	docker network create wordpress_net

	# 2. MySQL 데이터베이스 컨테이너 실행
	docker run -d --name "db" \
	  -v "$(pwd)/db_data:/var/lib/mysql" \
	  -e "MYSQL_ROOT_PASSWORD=123456" \
	  -e "MYSQL_DATABASE=wordpress" \
	  -e "MYSQL_USER=wordpress_user" \
	  -e "MYSQL_PASSWORD=123456" \
	  --network wordpress_net \
	  mysql:5.7

	# 3. 워드프레스 웹 애플리케이션 컨테이너 실행
	docker run -d --name app \
	  -v "$(pwd)/app_data:/var/www/html" \
	  -e "WORDPRESS_DB_HOST=db" \
	  -e "WORDPRESS_DB_USER=wordpress_user" \
	  -e "WORDPRESS_DB_NAME=wordpress" \
	  -e "WORDPRESS_DB_PASSWORD=123456" \
	  -e "WORDPRESS_DEBUG=1" \
	  -p 8080:80 \
	  --network wordpress_net \
	  wordpress:latest

2. [방법 B] Docker Compose 실행 과정 (추천)

	모든 인프라 설정을 문서화(Code)하여 명령어 한 줄로 동일한 환경을 복제할 수 있습니다.

	Step 1: 프로젝트 디렉토리 및 docker-compose.yml 생성
	
		mkdir -p /d/compose-test && cd /d/compose-test
		vi docker-compose.yml
		
		version: "3.7"

		services:
		  db:
		    image: mysql:5.7
		    restart: always
		    volumes:
		      - ./db_data:/var/lib/mysql
		    environment:
		      MYSQL_ROOT_PASSWORD: "123456"
		      MYSQL_DATABASE: "wordpress"
		      MYSQL_USER: "wordpress_user"
		      MYSQL_PASSWORD: "123456"

		  app:
		    image: wordpress:latest
		    restart: always
		    depends_on:
		      - db # db 컨테이너가 먼저 시작되도록 순서 보장
		    ports:
		      - "8080:80"
		    volumes:
		      - ./app_data:/var/www/html
		    environment:
		      WORDPRESS_DB_HOST: "db:3306" # 컨테이너 이름(db)으로 내부 통신
		      WORDPRESS_DB_NAME: "wordpress"
		      WORDPRESS_DB_USER: "wordpress_user"
		      WORDPRESS_DB_PASSWORD: "123456"

		:wq
		
	Step 2: 서비스 실행 및 관리
	
		# 1. 백그라운드에서 모든 서비스 일괄 기동
		docker compose up -d

		# 2. 작동 프로세스 및 상태 확인
		docker compose ps

		# 3. 서비스 중지 및 생성된 컨테이너, 내부 네트워크 일괄 삭제
		docker compose down

	
3. Docker Compose의 유용함과 핵심 메커니즘
	
	네트워크 자동 생성: 
		CLI 방식과 달리 네트워크를 직접 만들 필요가 없습니다. 
		도커 컴포즈는 디렉토리명을 기반으로 전용 격리 네트워크를 기본 생성하며, 
		내부 서비스들은 서비스명(db, app)을 도메인 주소처럼 사용하여 자동으로 통신합니다.
		
	
	의존성 제어 (depends_on): 
		웹 서버(app)가 데이터베이스(db)보다 먼저 켜져서 연결에 실패하는 문제를 방지하고 
		켜지는 순서를 조율합니다.

	볼륨 자동 마운트: 
		실행 위치에 app_data, db_data 폴더를 자동으로 생성하고 
		데이터를 보존하여 컨테이너가 복구되어도 데이터가 유지됩니다
		
4. Docker Compose 명령어 핵심 가이드
	
	⚠️ [필독] CLI 버전 변경 안내 (V1 ➡️ V2)
		
		구버전 스크립트나 블로그에서 자주 보이는 하이픈(-) 형태의 구문은 폐기되었습니다. 
		반드시 최신 표준 구문을 사용해야 합니다.
		
		❌ 과거 명령어 (V1): docker-compose up (2023년 공식 종료)
		⭕ 현재 표준 (V2): docker compose up (도커 엔진에 내장된 최신 규격, 띄어쓰기)
		
	! 필수 운영 명령어 요약
	
	생성 및 시작 : 이미지를 다운받고 컨테이너들을 백그라운드 구동
		docker compose up -d
		
	종료 및 삭제 : 컨테이너를 멈추고 컨테이너와 내부 네트워크까지 완벽 삭제
		docker compose down
		
	일시 정지 / 재개 : 개데이터나 컨테이너를 삭제하지 않고 가동만 제어
		docker compose stop / start
		
	실시간 로그 : 연동된 모든 컨테이너의 출력 로그를 한눈에 모니터링
		docker compose logs -f
