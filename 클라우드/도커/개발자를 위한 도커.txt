	도커데몬은 API를 제공한다
	
	CLI > API > 도커데몬(dockerd)

docker container run

	docker container run
	
	또는 (생략 버전)
	
	docker run
	
	은 같은 명령어이다.
	(Management Command 생략가능), 예: container

이미지, 컨테이너 와  metadata

	이미지는 압축파일 + metadata로 구성된다
	컨테이너도 이미지의  압축파일 + metadata를 복사해서 구동된다

이미지 metadata 확인

	docker image inspect nginx
	
컨테이너 metadata 확인 (실행 중일때만 가능)

	docker container inspect ws1
	
이미지 metadata 중 Cmd 속성 변경해서 실행하기
	
	실행시 이미지명 다음에 cmd '실행명령어'를 입력한다.
	없으면, 이미지 metadata에 설정된 '실행명령어'가 실행된다.

	(기본 실행을 덮어써서 실행하기, 바로 출력을 위해 -d 없이 실행)
	docker run --name ws1 nginx cat /usr/share/nginx/html/index.html
	
		..index.html 출력 후 프로세스 종료
	
	>docker container inspect ws1
	.. # 컨테이너 실행 상태에서 메타데이터 확인
	"Cmd": [
                "cat",
                "/usr/share/nginx/html/index.html"
            ],
	    
	: 생성된 컨테이너의 Cmd 명령어가 실행 변경된 것을 확인할 수 있다.     
	    
	    
이미지 metadata 중 Env 속성 변경해서 실행하기

	(기본 COLOR=red를 'blue'로 변경)
	docker run -d --name ws2 -p 8081:3000 --env COLOR=blue devwikirepo/envnodecolorapp
	
	>docker container inspect ws2
	.. # 컨테이너 실행 상태에서 메타데이터 확인
	"Env": [
                "COLOR=blue",
               ..
            ],

이미지 이름규칙
	
	레지스트리주소/프로젝트명/이미지명:이미지태그


	레지스트리주소:
		지정하지 않으면 기본 도커허브주소(docker.io)
		
	프로젝트명: 도커허브에서는 계정명이 프로젝트명
		공식 이미지명일때는 'library' 프로젝트명으로 고정.
		
	
	이미지명: 다운로드할 이미지명
	
	이미지태그: 이미지 버전
	
	예)	
	docker.io/library/nginx:latest
	
	도커허브에서는 docker.io/library 는 생략가능(공식이미지일때)
	그러므로 아래처럼 생략된 이름으로 pull 가능.
	
		docker pull nginx:latest
		또는
		docker pull nginx
	
	(개인계정 이미지)
	docker.io/solgae/mynginx:1.0
	solgae/mynginx:1.0
	
	
	(도커허브가 아닌 다른 레지스트리)
	solgae.com/androidApp/mynginx:1.0
	
	
이미지 버전
	
	Docker Official: 공식 이미지
	DHI(Docker Hardened Images)
		: '다이어트와 보안 방탄조끼를 입힌 도커 이미지'
	stable: 안정적 버전
	slim: 전송시간을 줄일 수 있는 크기지만, 디버깅은 어려운 최소화 버전
	alpine: 경량버전위 OS탑재 버전
		
	
docker tag: 이미지에 새로운 tag 부여
		
	본인의 도커허브 개인 저장소에 올리려면 반드시 '내ID/이미지명:태그' 형태로 
	이미지 이름을 새로 만들어서 push 해야 합니다.
	
	커스텀 이미지 아니더라도 tag 명령어로 새로운 이름의 태그를 달아서 
	자신의 계정에 업로드할 수 있습니다.
	
	실습)	
	docker pull nginx
	docker tag nginx:latest solgae/myNginx:1.0
	docker push solgae/myNginx:1.0
	
이미지 레이어

	docker image history 명령어로 이미지 레이어 이력 확인 가능.
	동일한 레이어는 중복 저장되지 않고 재사용됨.
	한번 생성된 레이어는 불변(immutable)이며,고유 해시값을 가진다(읽기 전용).
	Copy-On-Write(COW)는 이미지 관리 핵심 원칙.
	COW: 이미지 레이어를 쌓아가며 이전 레이어를 수정하는 방식.
	
이미지 커밋
	이미지 제작방식은 commit, build 방식이 있다.
	build 방식도 commit 방식을 기반으로 한다
	
	commit 방식은 실행 중인 컨테이너의 현재 상태를 이미지로 저장하는 방식.
	
	예)
	docker commit -m "edited index.html by solgae" -c "CMD [\"nginx\",\"-g\",\"daemon off;\"]" ws1 solgae/commitnginx 
	

이미지 빌드
	도커는 lac 방법론을 활용해 도커파일(Dockerfile)이라는 파일로 파일 시스템의 상태를 정의하고, 
	이를 기반으로 이미지를 만듭니다.
	
	빌드명령어 형식)
	docker build -t [이미지명] [도커파일 경로]
	
		$ docker build -t solgae/my-nginx:latest .
	
	[도커파일 경로] root에 'Dockerfile'이 위치해야 이 파일을 도커가 읽고 빌드합니다.
	
이미지 build -t 옵션

	-t 옵션: 뒤에 '이미지명:태그' 형식을 기입할 수 있게된다
		이 옵션을 쓰지 않으면 이미지명이 해시ID로 저장되므로,
		다시 참조하기가 힘들어진다.
		그러므로 무조건 build -t [이미지명:태그] 는
		한 셋트로 인식하는게 좋다
		
이미지 built -f 옵션
	
	기본 지정하지 않으면 현재 build 명령어 하는 위치의 'Dockerfile'을 찾는다.
	만약 도커파일이 'Dockerfile'로 안 되어 있고, 커스텀이라면(Dockerfile-build)
	이럴때 -f 옵션을 지정한다
	
	$ docker build -f Dockerfile-build -t solgae/my-nginx
	
	
빌드 컨텍스트
	Dockerfile 이 있는 곳이 빌드 컨텍스트다
	도커 이미지를 빌드하는 필요한 모든 자원들이 있는 root폴더
	용어를 '빌드 컨텍스트' 라고 부른다. 익숙해지자.
	
.dockerignore 파일
	
	Dockerfile 과 같은 위치에 이 파일을 생성하고, 제외할 파일명이나
	폴더명등을 기입한다. 
	
	빌드 컨텍스트 안에서 빌드에 제외할 자원을 .dockerignore 에 
	지정하면 빌드에서 제외된다.
	
Dockerfile 지시어 (형식 맛보기)

	FROM '베이스 이미지명'
	COPY [커스텀 소스파일경로] [복사할 경로]
	CMD ["컨테이너 시작시 명령어"]
	
	 # CMD 명령어는 metadata의 CMD 필드에 저장된다.
	
	(실제코드)
	Dockerfile: 
		FROM nginx:1.23
		COPY index.html /usr/share/nginx/html/index.html
		CMD ["nginx", "-g", "daemon.off;"]
		
	
각 지시어는 새 이미지 레이어 생성(추가)여부로 구분할 수 있다.

	- 새 이미지를 생성하는 지시어(파일 시스템을 바꾸는 것)
		: COPY, RUN, ADD 
		
	- 새 이미지 레이어를 생성하지 않는 지시어(설정값만 바꾸는 것)
		: EXPOSE , ENV, WORKDIR, CMD, ENTRYPOINT
		
Dockerfile 
	
	FROM: 
		베이스 이미지 지정
	WORKDIR:
		작업 디렉토리 설정(리눅스의 cd 명령어 역할)
		이후 나오는 RUN, COPY, CMD 등은 
		모두 이 폴더를 기준으로 동작
		
		만약 폴더가 없으면 자동으로 만들어 줍니다. 
		Metatdata만 수정하므로 레이어를 생성하지 않습니다
		
		예시: WORKDIR /app
	COPY: 
		빌드 컨텍스트의 파일을 복사하여 새로운 이미지 레이어 생성
	
	ADD: 
		COPY의 확장 버전. 
		URL 다운로드 및 압축 파일(tar 계열) 자동 해제 기능 포함 
		(ZIP 제외, 새로운 이미지 레이어 생성)
		
		(공식문서에서는 이 지시어 추천하지 않음)
	
	RUN: 
		이미지 빌드 단계에서 명령어 실행. 
		패키지 설치 등에 쓰이며 새로운 이미지 레이어 생성
		
	ARG: 
		이미지 빌드할 때만 임시로 사용할 변수 
		(최종 이미지에는 남지 않음)
	
	ENV: 
		이미지 빌드 단계는 물론, 컨테이너 실행 중에도 계속 유지되는 
		환경 변수 (이미지 메타데이터에 저장)
		
	ENTRYPOINT: 
		(고정된 강제 실행 명령어)
		주로 CMD와 조합해서 사용합니다
		
		예시: ENTRYPOINT ["python"] + CMD ["main.py"] 
		(기본값은 python main.py로 실행되지만, 사용자가 뒤에 다른 파일명을 입력하면 파일명만 바뀜)
	
	CMD: 
		컨테이너 시작 시 실행될 기본 명령어 지정. 
		이미지 메타데이터(Cmd)만 수정하며, 
		별도의 레이어는 생성하지 않음
		
	EXPOSE: 
		컨테이너 내부에서 사용할 포트를 명시하는 공식 명세서. 
		이미지 메타데이터만 수정하며, 별도의 레이어는 생성하지 않음
		
run -it 와 exec -it 차이

	처음 만들어서 확인해 볼 때: 
		docker run -it --name test ubuntu /bin/bash

	이미 켜둔 컨테이너(예: MySQL 등)에 들어가 볼 때: 
		docker exec -it mysql-db /bin/bash
	
멀티 스테이지 빌드
	앱 빌드와 이미지 빌드를 나눠서 하고, 최종 결과물엔 
	앱 빌드 산출물만 포함시켜 구동시키는 방식.
	(당연히 용량 절감)
	
	----- Dockerfile-multi
	
	FROM maven:3.6 AS build
	WORKDIR /app
	COPY pom.xml .
	COPY src ./src
	RUN mvn clean package

	FROM azul/zulu-openjdk-alpine:11-jre
	WORKDIR /app
	COPY --from=build /app/target/demo-0.0.1-SNAPSHOT.jar ./app.jar
	EXPOSE 8080
	CMD ["java","-jar","app.jar"]
