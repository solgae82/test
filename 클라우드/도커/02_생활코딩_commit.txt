[Docker] docker commit 명령어 핵심 정리

	docker commit은 실행 중인 컨테이너의 변경 사항(파일 추가, 패키지 설치 등)을 
	특정 시점의 새로운 이미지로 저장하는 명령어입니다.

	Git의 커밋처럼 컨테이너의 상태를 백업하거나 재활용할 때 사용합니다.

1. 기본 명령어 구조

	docker commit [옵션] <컨테이너_ID 또는 이름> <새로운_이미지명>:<태그>

2. 주요 옵션
	
	-m, --message: 커밋 메시지(변경 사항) 입력
	-a, --author: 이미지 작성자 정보 입력
	-p, --pause: 커밋 생성 중 컨테이너를 일시 정지 (기본값: true)
	
	(Tip: 데이터 일관성을 위해 켜두는(기본값) 것이 안전합니다.)
	
3. 실무 작업 흐름 (Workflow)	
	
	
	1) 컨테이너 실행
	
		docker run -it --name my-container ubuntu:20.04

	2) 컨테이너 내부 수정 (예: 패키지 설치)
	
		apt-get update && apt-get install -y git
		
	
	3) 변경 사항을 새 이미지로 저장
	
		docker commit -m "install git" -a "dong" my-container my-ubuntu-git:v1


	4) 생성된 이미지 확인 및 실행
	
		docker images
	
		docker run -it my-ubuntu-git:v1
	
		
4. 주의사항 및 권장사항 (중요)
	Dockerfile 사용 권장: 
	
		docker commit은 임시 백업에는 유용하지만, 
		이미지 생성 과정의 히스토리(명령어 기록)가 남지 않아 추후 관리가 어렵습니다. 
		실무에서는 자동화와 투명성을 위해 Dockerfile을 통한 이미지 빌드(docker build)가 권장됩니다.
	
	데이터 일관성: 
		컨테이너가 가동 중일 때도 커밋은 가능하지만, 
		파일 쓰기 작업이 빈번한 경우 데이터 깨짐을 방지하기 위해 
		컨테이너를 정지(docker stop)한 후 커밋하거나 -p 옵션(기본 활성화)을 유지하는 것이 좋습니다.
